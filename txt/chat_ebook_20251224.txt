### 方案二：统一日志输出到同一文件
#### 2.1 重定向System.out到Log4j2
**创建：** `src/com/seeyon/ctp/common/log/SystemOutRedirector.java`
```java
package com.seeyon.ctp.common.log;
import org.apache.commons.logging.Log;
import java.io.PrintStream;
import java.io.OutputStream;
/**
*/
* 将System.out/System.err重定向到Log4j2
public class SystemOutRedirector {
private static final Log logger = CtpLogFactory.getLog(SystemOutRedirector.class);
private static boolean redirected = false;
/**
* 启动重定向
*/
public static synchronized void redirect() {
if (redirected) {
return;
}
// 保存原始输出流（用于特殊情况）
PrintStream originalOut = System.out;
PrintStream originalErr = System.err;
// 重定向 System.out 到 INFO 级别
System.setOut(new PrintStream(new LogOutputStream(logger, LogLevel.INFO), true));
// 重定向 System.err 到 ERROR 级别
System.setErr(new PrintStream(new LogOutputStream(logger, LogLevel.ERROR), true));
redirected = true;
logger.info(\"System.out/System.err已重定向到日志系统\");
}
/**
* 日志输出流
*/
private static class LogOutputStream extends OutputStream {
private final Log logger;
private final LogLevel level;
private final StringBuilder buffer = new StringBuilder();
public LogOutputStream(Log logger, LogLevel level) {
this.logger = logger;
this.level = level;
}
@Override
public void write(int b) {
if (b == '\
') {
flush();
} else if (b != '\
') {
buffer.append((char) b);
}
}
@Override
public void flush() {
if (buffer.length() > 0) {
String message = buffer.toString();
switch (level) {
case INFO:
logger.info(\"[SYSOUT] \" + message);
break;
case ERROR:
logger.error(\"[SYSERR] \" + message);
break;
}
buffer.setLength(0);
}
}
}
enum LogLevel {
INFO, ERROR
}
}
```

### 方案C：自动化工具处理
#### 3.5 使用JavaParser进行AST级别替换
**创建工具类：** `LogMigrationTool.java`
```java
package com.seeyon.tools;
import com.github.javaparser.JavaParser;
import com.github.javaparser.ast.CompilationUnit;
import com.github.javaparser.ast.body.ClassOrInterfaceDeclaration;
import com.github.javaparser.ast.expr.MethodCallExpr;
import com.github.javaparser.ast.stmt.ExpressionStmt;
import java.io.File;
import java.io.FileWriter;
import java.nio.file.Files;
/**
*/
* System.out自动迁移到Logger工具
public class LogMigrationTool {
public static void main(String[] args) throws Exception {
String projectRoot = \"/Users/myu/github/seeyon8.0/src\";
migrateDirectory(new File(projectRoot));
}
public static void migrateDirectory(File dir) throws Exception {
File[] files = dir.listFiles();
if (files == null) return;
for (File file : files) {
if (file.isDirectory()) {
migrateDirectory(file);
} else if (file.getName().endsWith(\".java\")) {
migrateFile(file);
}
}
}
public static void migrateFile(File file) throws Exception {
String content = new String(Files.readAllBytes(file.toPath()));
// 解析Java文件
CompilationUnit cu = new JavaParser().parse(content).getResult().get();
// 查找所有System.out.println调用
boolean modified = false;
for (MethodCallExpr methodCall : cu.findAll(MethodCallExpr.class)) {
if (methodCall.getScope().isPresent() &&
methodCall.getScope().get().toString().equals(\"System.out\") &&
methodCall.getNameAsString().equals(\"println\")) {
// 检查类中是否有logger字段
ClassOrInterfaceDeclaration clazz = methodCall.findAncestor(ClassOrInterfaceDeclaration.class).get();
if (!hasLoggerField(clazz)) {
addLoggerField(clazz);
}
// 替换System.out.println为logger.info
String arg = methodCall.getArgument(0).toString();
methodCall.setScope(null);
methodCall.setName(\"logger.info\");
modified = true;
}
}
// 保存修改
if (modified) {
try (FileWriter writer = new FileWriter(file)) {
writer.write(cu.toString());
}
System.out.println(\"已修改: \" + file.getPath());
}
}
private static boolean hasLoggerField(ClassOrInterfaceDeclaration clazz) {
return clazz.getFieldByName(\"logger\").isPresent();
}
private static void addLoggerField(ClassOrInterfaceDeclaration clazz) {
String loggerField = \"private static final Log logger = CtpLogFactory.getLog(\" +
clazz.getNameAsString() + \".class);\";
clazz.addFieldWithInitializer(\"Log\", \"logger\",
JavaParser.parseExpression(\"CtpLogFactory.getLog(\" + clazz.getNameAsString() + \".class)\"),
com.github.javaparser.ast.Modifier.Keyword.PRIVATE,
com.github.javaparser.ast.Modifier.Keyword.STATIC,
com.github.javaparser.ast.Modifier.Keyword.FINAL);
// 添加import
CompilationUnit cu = clazz.findCompilationUnit().get();
cu.addImport(\"org.apache.commons.logging.Log\");
cu.addImport(\"com.seeyon.ctp.common.log.CtpLogFactory\");
}
}
```

```java
public static void error(String message, Throwable throwable) {
logger.error(message, throwable);
/**
* 输出ERROR级别日志（支持占位符）
* @param message 日志消息模板
* @param args 参数值（最后一个参数如果是Throwable，会作为异常处理）
*/
public static void error(String message, Object... args) {
if (args.length > 0 && args[args.length - 1] instanceof Throwable) {
// 最后一个参数是异常
Object[] params = new Object[args.length - 1];
System.arraycopy(args, 0, params, 0, params.length);
logger.error(formatMessage(message, params), (Throwable) args[args.length - 1]);
} else {
logger.error(formatMessage(message, args));
}
}
/**
* 格式化日志消息（支持{}占位符）
* @param message 消息模板
* @param args 参数
* @return 格式化后的消息
*/
private static String formatMessage(String message, Object... args) {
if (args == null || args.length == 0) {
return message;
}
String result = message;
for (Object arg : args) {
if (arg instanceof Throwable) {
continue; // 跳过异常对象
}
}
return result;
}
result = result.replaceFirst(\"\\\\{\\\\}\", String.valueOf(arg));
/**
* 获取原始Logger对象（高级用法）
* @return Log对象
*/
public static Log getLogger() {
return logger;
}
}

```

```
↓
```

1. **CtpLogFactory 已支持字符串参数**

2. **Log4j2 根据Logger名称路由**
```xml

<AppenderRef ref=\"thirdparty\"/>
</AsyncLogger>
```
3. **完全利用现有机制**
- 不需要新类
- 不需要修改现有代码
- 只需配置路由规则

## FAQ
**Q1：为什么不需要新增类？**
A：CtpLogFactory 已经支持 `getLog(String name)`，直接使用即可。
**Q2：参数必须是 \"thirdparty\" 吗？**
A：必须与配置文件中的 `<AsyncLogger name=\"thirdparty\">` 一致。
**Q3：可以改成其他名字吗？**
A：可以，同步修改配置文件中的 name 即可，比如改成 \"custom\"。
**Q4：会影响原有日志吗？**
A：完全不会，这是新增的独立Logger，与原有系统隔离。
**Q5：需要重启系统吗？**
A：是的，修改Log4j2配置需要重启才能生效。
**Q6：如何修改日志级别？**
A：修改 `<AsyncLogger level=\"info\"` 为 debug/warn/error。
**Q7：支持按包名路由吗？**
A：支持，比如配置 `name=\"com.seeyon.custom\"`，则该包下所有使用 `getLog(Class)` 的日志会路由到这里。
但推荐使用固定名称 \"thirdparty\"，更清晰。

#### 2.2.3 CAP4数据转换器
**类名：** `FormtalkTrans2CAP4Impl`
**路径：** `src/com/seeyon/apps/formtalk/event/FormtalkTrans2CAP4Impl.java`
```java
/**
* Formtalk数据转换为CAP4表单数据
* 这是整个导入流程的核心转换引擎
*/
public class FormtalkTrans2CAP4Impl implements FormtalkTrans2CAP4 {
/**
* 转换主方法
*
* @param ftInterVer Formtalk接口版本(v0/v1)
* @param formtalkFormId Formtalk表单ID
* @param formtalkDataId Formtalk数据ID
* @param formBeanId CAP4表单Bean ID
* @param formType 表单类型(0=流程表单/1=非流程表单)
* @param dataMap Formtalk主表数据映射(中文字段名→值)
* @param dataColumnMap 列数据映射
* @param confieldMap 配置字段映射
* @param isConfInsert 是否允许新建记录
* @param loginName 登录用户名
* @param templateCode 模板编码
* @return 主表数据ID
*/
public String transferFormtalk2OA(
String ftInterVer,
String formtalkFormId,
String formtalkDataId,
long formBeanId,
int formType,
Map<String, String> dataMap,
Map<String, Object> dataColumnMap,
List<Map<String, String>> confieldMap,
boolean isConfInsert,
String loginName,
String templateCode
) throws Exception {
// ========== 第一步：获取表单定义 ==========
FormBean formBean = formApi4Cap4.getForm(formBeanId);
if (formBean == null) {
throw new BusinessException(\"表单不存在: \" + formBeanId);
}
// 获取主表定义
FormTableBean masterTable = formBean.getMasterTableBean();
// ========== 第二步：数据导出封装 ==========
// 根据版本选择不同的导出工具
FormExportPack exportPack;
if (\"v1\".equals(ftInterVer)) {
exportPack = ExportFormUtil4CAP4V1.FormExport(
currentMember, // 当前操作员
formBean, // 表单定义
dataMap, // Formtalk数据
dataColumnMap, // 列数据
errorMsg // 错误信息缓冲区
);
} else {
exportPack = ExportFormUtil4CAP4V0.FormExport(
currentMember,
formBean,
dataMap,
dataColumnMap,
errorMsg
);
}
FormExport formExport = exportPack.getExport();
// ========== 第三步：查询是否已存在数据 ==========
Long masterId = FormDBUtil4CAP4.getMasterId(
formBean,
dataMap
);
boolean isUpdate = (masterId != null);
if (isUpdate) {
// 更新模式
logger.info(\"找到已存在数据，主表ID: {}\", masterId);
} else {
// 新建模式
if (!isConfInsert) {
throw new BusinessException(\"不允许新建记录\");
}
logger.info(\"未找到已存在数据，将新建记录\");
}
// ========== 第四步：构建主表数据Bean ==========
FormDataMasterBean masterBean;
if (isUpdate) {
// 加载现有数据
masterBean = formApi4Cap4.getFormData(formBeanId, masterId);
} else {
// 创建新数据
masterBean = new FormDataMasterBean();
masterBean.setStartMemberId(currentMember.getId());
masterBean.setStartDate(new Date());
}
// ========== 第五步：填充主表字段值 ==========
for (ValueExport valueExport : formExport.getValues()) {
String fieldName = valueExport.getFieldName();
Object fieldValue = valueExport.getValue();
// 获取字段定义
FormFieldBean field = masterTable.getFieldBeanByName(fieldName);
if (field == null) {
logger.warn(\"字段不存在: {}\", fieldName);
continue;
}
// 类型转换
Object convertedValue = convertFieldValue(field, fieldValue);
// 添加到数据Bean
masterBean.addFieldValue(fieldName, convertedValue);
logger.debug(\"字段[{}]赋值: {}\", field.getDisplay(), convertedValue);
}
// ========== 第六步：处理子表数据 ==========
if (formExport.getSubordinateForms() != null) {
for (SubordinateFormExport subExport : formExport.getSubordinateForms()) {
String subTableName = subExport.getSubordinateTableName();
FormTableBean subTable = formBean.getTableByName(subTableName);
if (subTable == null) {
logger.warn(\"子表不存在: {}\", subTableName);
continue;
}
// 处理子表行数据
List<FormDataSubBean> subDataList = new ArrayList<>();
int sort = 1;
for (List<ValueExport> subRow : subExport.getValueLists()) {
FormDataSubBean subBean = new FormDataSubBean();
subBean.setSort(sort++);
// 填充子表字段
for (ValueExport valueExport : subRow) {
String fieldName = valueExport.getFieldName();
Object fieldValue = valueExport.getValue();
FormFieldBean field = subTable.getFieldBeanByName(fieldName);
if (field == null) continue;
Object convertedValue = convertFieldValue(field, fieldValue);
subBean.addFieldValue(fieldName, convertedValue);
}
subDataList.add(subBean);
}
// 更新子表策略
if (isUpdate) {
// 删除旧数据，插入新数据
masterBean.removeSubData(subTableName);
}
for (FormDataSubBean subBean : subDataList) {
masterBean.addSubData(subTableName, subBean);
}
logger.info(\"子表[{}]处理完成，行数: {}\",
subTable.getDisplay(), subDataList.size());
}
}
// ========== 第七步：保存数据到数据库 ==========
Long savedMasterId = formApi4Cap4.saveOrUpdateFormData(
formBeanId, // 表单ID
masterBean, // 主表数据Bean
null, // 扩展参数
true // 是否触发事件
);
logger.info(\"表单数据保存成功，主表ID: {}\", savedMasterId);
// ========== 第八步：触发表单事件 ==========
CAP4FormTriggerFireEvent triggerEvent = new CAP4FormTriggerFireEvent(
formBeanId,
savedMasterId,
isUpdate ? \"update\" : \"save\"
);
eventPublisher.publishEvent(triggerEvent);
// ========== 第九步：导入附件 ==========
Map<Long, AttachmentPack> attachmentMap = exportPack.getAttMap();
if (attachmentMap != null && !attachmentMap.isEmpty()) {
importFormAttachment(
formBeanId,
savedMasterId,
attachmentMap
);
logger.info(\"附件导入完成，数量: {}\", attachmentMap.size());
}
return savedMasterId.toString();
}
/**
* 字段值类型转换
*/
private Object convertFieldValue(FormFieldBean field, Object value) {
if (value == null) return null;
String fieldType = field.getFieldType();
switch (fieldType) {
case \"DECIMAL\":
// 数字类型
if (value instanceof String) {
return new BigDecimal((String) value);
}
return value;
case \"DATETIME\":
// 日期时间类型
if (value instanceof String) {
SimpleDateFormat sdf = new SimpleDateFormat(\"yyyy-MM-dd HH:mm:ss\");
return sdf.parse((String) value);
}
return value;
case \"DATE\":
// 日期类型
if (value instanceof String) {
SimpleDateFormat sdf = new SimpleDateFormat(\"yyyy-MM-dd\");
return sdf.parse((String) value);
}
return value;
case \"INT\":
case \"BIGINT\":
// 整数类型
if (value instanceof String) {
return Long.parseLong((String) value);
}
return value;
default:
// 文本类型
return value.toString();
}
}
}
```

```java
sql.append(\" WHERE 1=1\");
List<Object> params = new ArrayList<>();
// 遍历配置的匹配字段
for (Map.Entry<String, String> entry : dataMap.entrySet()) {
String ftFieldName = entry.getKey(); // Formtalk字段名
String ftFieldValue = entry.getValue(); // Formtalk字段值
// 查找对应的OA字段
FormFieldBean field = masterTable.getFieldBeanByDisplay(ftFieldName);
if (field == null) continue;
// 添加查询条件
sql.append(\" AND \").append(field.getColumnName()).append(\" = ?\");
params.add(ftFieldValue);
}
// 执行查询
List<Map<String, Object>> result = jdbcTemplate.queryForList(
sql.toString(),
params.toArray()
);
if (result.isEmpty()) {
return null; // 不存在
}
return (Long) result.get(0).get(\"id\");
}
```

## 三、CAP4表单引擎架构
### 3.1 核心设计思想
**1. Bean-Oriented（面向Bean）**
```
FormBean 表单定义Bean（容器）
├── FormTableBean 表结构Bean
│ └── FormFieldBean 字段定义Bean
├── FormViewBean 视图Bean
├── FormTriggerBean 触发器Bean
└── FormBindBean 应用绑定Bean
FormDataMasterBean 主表数据Bean（容器）
└── FormDataSubBean 子表数据Bean
```
**2. Separation of Concerns（关注点分离）**
```
设计层 (design) - 表单设计、字段配置
数据层 (data) - 数据CRUD操作
授权层 (authorization) - 权限控制
触发层 (trigger) - 业务触发器
关系层 (relation) - 数据关系
公式层 (formula) - 公式计算
```
**3. Metadata-Driven（元数据驱动）**
```
CAP_FORM_DEFINITION表
├── field_info (JSON) → 动态生成字段
├── view_info (JSON) → 动态渲染页面
├── app_bind_info (JSON) → 动态绑定应用
└── extensions_info (JSON) → 动态扩展功能
```

```java
if (value == null) return null;
String fieldType = field.getFieldType();
switch (fieldType) {
case \"TEXT\":
case \"TEXTAREA\":
return value.toString();
case \"DECIMAL\":
if (value instanceof String) {
return new BigDecimal((String) value);
} else if (value instanceof Number) {
return new BigDecimal(value.toString());
}
return value;
case \"DATETIME\":
if (value instanceof String) {
SimpleDateFormat sdf = new SimpleDateFormat(\"yyyy-MM-dd HH:mm:ss\");
try {
return sdf.parse((String) value);
} catch (ParseException e) {
throw new RuntimeException(\"日期格式错误: \" + value);
}
}
return value;
case \"DATE\":
if (value instanceof String) {
SimpleDateFormat sdf = new SimpleDateFormat(\"yyyy-MM-dd\");
try {
return sdf.parse((String) value);
} catch (ParseException e) {
throw new RuntimeException(\"日期格式错误: \" + value);
}
}
return value;
case \"INT\":
case \"BIGINT\":
if (value instanceof String) {
return Long.parseLong((String) value);
}
return value;
default:
return value;
}
}

return null;
}
}
```

## 四、设计思想深度解析
### 4.1 元数据驱动设计
**核心理念：**
```
配置 > 代码
数据 > 逻辑
灵活 > 固定
```
**实现方式：**
1. **JSON配置存储**
- 字段定义、视图配置、触发器规则全部存储为JSON
- 修改配置无需重新编译代码
- 支持动态字段、动态视图
2. **运行时解析**
- 从数据库加载JSON配置
- 解析为FormBean、FormTableBean等对象
- 渲染页面、验证数据、执行业务逻辑
3. **优点：**
- 快速迭代：修改配置立即生效
- 易于扩展：新增字段只需修改JSON
- 版本管理：配置即代码，易于版本控制

### 4.2 为什么这些代码是必要的？
#### 核心原因分析：
**1. 工作流流转（681行）- 最核心**
```java
wfInfo = this.govdocWorkflowManager.zcdbRuncase(handleType, dealVo);
```
**原因：**
- 这是工作流引擎的调用，决定公文流转到哪里
- \"zcdb\"=暂存待办，表示已阅后不流转，保持在当前节点
- 返回的WFInfo包含流转结果、下一步处理人等信息
**不执行会导致：**
- 工作流状态不更新
- 下一步处理人无法确定
- 流程无法继续
---
**2. 更新affair表（745行）- 核心**
```java
this.affairManager.updateAffair(affair);
```
**原因：**
- affair是待办事项记录，存储在`ctp_affair`表
- 已阅后需要更新：
- `state`: 状态（待办→已办）
- `sub_state`: 子状态（暂存待办）
- `update_date`: 更新时间
- `read_state`: 阅读状态（未读→已读）
**不执行会导致：**
- 待办列表中仍显示未读
- 无法标记为已处理
- 统计数据错误
---
**3. 更新summary表（746行）- 核心**
```java
this.govdocSummaryManager.updateEdocSummary(summary);
```
**原因：**
- summary是公文摘要，存储在`edoc_summary`表
- 已阅后需要更新：
- `current_nodes`: 当前节点信息
- `state`: 流程状态
- 其他业务字段
**不执行会导致：**
- 公文状态不更新
- 流程追踪错误
- 监控统计错误
---
**4. 保存意见（652-662行）**
```java
```
Comment newComment = this.govdocCommentManager.insertComment(comment, affair);
**原因：**
- 已阅时用户可能填写意见（如\"已阅知\"）
- 意见需要持久化到`ctp_comment`表
- 意见是审批痕迹的重要组成部分
**不执行会导致：**
- 已阅意见丢失
- 审批痕迹不完整
---
**5. 发送消息（674、683行）**
```java
this.govdocMessageManager.sendOperationTypeMessage(...);
this.govdocMessageManager.sendMessage4Zcdb(affair, comment);
```
**原因：**
- 通知相关人员（如发起人、下一步处理人）
- 系统消息、邮件、短信等
- 提醒机制的一部分
**不执行会导致：**
- 相关人员不知道公文已被阅读
- 流程进度不透明
---
**6. 记录日志（682行）**
```java
```
this.govdocLogManager.insertProcessLog(..., ProcessLogAction.zcdb, ...);
**原因：**
- 记录流程轨迹（谁、何时、做了什么）
- 审计需要
- 流程监控、统计分析
**不执行会导致：**
- 流程轨迹不完整
- 无法追溯
- 监控盲区
---
**7. 更新全文索引（756行）**

## 七、常见问题与解答
### Q1：为什么已阅也要调用工作流引擎？
**A：** 因为工作流引擎负责：
1. 更新affair的流程状态
2. 判断是否流程结束
3. 计算下一步处理人（即使不流转，也需要记录）
4. 返回流转结果（WFInfo）
即使是\"暂存待办\"（不流转），也需要工作流引擎更新状态。
---
### Q2：zcdbRuncase 和 finishRuncase 的区别？
**A：**
| 方法 | 中文名 | 流转 | 状态 |
|------|--------|------|------|
| `zcdbRuncase` | 暂存待办 |   不流转 | 待办 |
| `finishRuncase` | 完成 |   流转到下一节点 | 已办 |
**zcdbRuncase流程：**
```
当前节点 → 暂存待办状态 → 仍在当前节点 → affair状态=待办
```
**finishRuncase流程：**
```
当前节点 → 完成 → 流转到下一节点 → affair状态=已办
```
---
### Q3：为什么已阅后affair还是待办状态？
**A：** 因为\"已阅\"的设计理念是：
- 已经阅读过了（`read_state`=已读）
- 但还没有正式办理（`state`=待办）
- 处于\"暂存待办\"状态（`sub_state`=col_pending_ZCDB）
这样设计的好处：
1. 用户可以先阅读，稍后再办理
2. 流程不会直接流转，给用户思考时间
3. 符合公文审批的实际业务场景
---
### Q4：如果只想标记已读，不触发其他逻辑，怎么办？

```java
// 更新消息状态
userMessageManager.updateSystemMessageStateByUserAndReference(
AppContext.currentUserId(),

);
}
```
**注意：** 这种方式只更新阅读状态，不触发工作流和业务逻辑。
